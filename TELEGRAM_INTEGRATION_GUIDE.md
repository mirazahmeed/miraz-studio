# Miraz Studio & Existing Telegram Bot Integration Guide

This guide details how **Miraz Studio** connects to your **EXISTING Telegram bot** as a second application source without creating a new bot, without modifying or breaking your existing personal portfolio functionality, and respecting the single Telegram webhook rule.

---

## 1. Architectural Overview

```
                        Existing Telegram Bot
                                 │
                                 ▼
                     Existing Personal Webhook
                        (mirazahmed.com)
                                 │
                          Command Router
                         /              \
                        ▼                ▼
                 [👤 Personal]    [🏢 Miraz Studio]
                   existing         authenticated
                    logic           server-to-server
                                         │
                                         ▼
                                   mirazstudio.xyz
                                    /api/telegram
                                         │
                                         ▼
                                   Studio Database
```

- **One Bot**: The existing Telegram bot remains the single bot for both applications.
- **Single Webhook**: Telegram dispatches updates to your existing central webhook on `mirazahmed.com`.
- **Authenticated Inter-Service Forwarding**: Updates for Miraz Studio are forwarded using a private server-to-server `Bearer` secret (`STUDIO_TELEGRAM_INTERNAL_SECRET`).
- **Source Label**: Every message generated by Miraz Studio starts with:
  ```
  🏢 MIRAZ STUDIO
  ━━━━━━━━━━━━━━━━
  ```
- **Transaction Safety**: Studio contact submissions save to the Miraz Studio database **first**. If the Telegram API fails or times out, the lead remains safely saved, and the visitor receives a success response.

## 2. Environment Variables Required

In your Miraz Studio `.env` file (see [`.env.example`](file:///Users/mirazahmed/Desktop/Prog/Projects/miraz-studio/mirazstudio/.env.example)), add the exact credentials from your existing Personal Portfolio bot:

```bash
# Use the SAME values from your existing Personal Portfolio bot
TELEGRAM_BOT_TOKEN="YOUR_EXISTING_TELEGRAM_BOT_TOKEN"
TELEGRAM_ADMIN_CHAT_ID="YOUR_EXISTING_TELEGRAM_ADMIN_CHAT_ID"

# Server-to-Server Internal Secret (Must match in BOTH applications)
STUDIO_TELEGRAM_INTERNAL_SECRET="YOUR_SHARED_INTERNAL_SECRET"
```

> **Security Note**: These variables are **server-only**. They are never exposed to client bundles, public API responses, or browser JavaScript.

## 3. What Was Implemented in Miraz Studio

1. **Central Notification Service (`src/lib/telegram.ts`)**:
   - `formatStudioTelegramMessage()`: Centrally prepends `🏢 MIRAZ STUDIO\n━━━━━━━━━━━━━━━━`.
   - `escapeHtml()`: Escapes user inputs (`<`, `>`, `&`, `"`, `'`) to prevent Telegram HTML injection.
   - `sendStudioNewLeadNotification()`: Dispatches lead alerts to the admin with inline actions:
     - `[👁 View]` (`studio:lead:view:<id>`)
     - `[📖 Mark Read]` (`studio:lead:read:<id>`)
     - `[📦 Archive]` (`studio:lead:archive:<id>`)
   - **Request Timeout**: All Telegram API requests enforce an explicit 5-second timeout (`AbortSignal.timeout(5000)`).
   - `getStudioDashboardData()`: Real-time counts of new leads and active projects.
   - `getStudioLeadsData()`: Paginated recent inquiries with database status emojis (`🟡 New`, `🟢 Read`, `🔴 Archived`, `🔵 Replied`).
   - `getStudioProjectsData()`: Paginated live studio case studies.
   - `isAuthorizedAdmin()`: Strictly limits access to `TELEGRAM_ADMIN_CHAT_ID`.

2. **Lead Submission Trigger (`src/app/actions/contact.ts`)**:
   - Inquiries are written to `prisma.contactMessage` **first**.
   - Telegram notifications are dispatched with safe error catching so that Telegram network failures or timeouts never roll back or fail lead creation.

3. **Secure Studio Webhook Endpoint (`src/app/api/telegram/route.ts`)**:
   - **Internal Secret Verification**: Verifies `Authorization: Bearer <STUDIO_TELEGRAM_INTERNAL_SECRET>` before processing any payload. Returns `HTTP 401 Unauthorized` if invalid.
   - Handles `/studio`, `/studio_leads`, `/studio_projects` commands.
   - Handles `studio:lead:view:*`, `studio:lead:read:*`, and `studio:lead:archive:*` callbacks.
   - **Idempotency**: Prevents duplicate updates if an already read or archived lead is clicked again.
   - **Safe Logging**: Structured logging without exposing bot tokens, internal secrets, or full auth headers.

## 4. Connecting Your Existing Central Webhook (2-Minute Setup)

In your existing Personal Portfolio webhook handler (e.g. `mirazahmed.com/api/telegram/webhook`), add this router check at the beginning:

```typescript
// Inside your existing Telegram webhook POST handler on mirazahmed.com:
const text = update.message?.text || "";
const callbackData = update.callback_query?.data || "";

// Route Studio commands and callback queries to Miraz Studio
if (
  text.startsWith("/studio") ||
  callbackData.startsWith("studio:")
) {
  try {
    const studioUrl = process.env.MIRAZ_STUDIO_URL || "https://mirazstudio.xyz";
    const internalSecret = process.env.STUDIO_TELEGRAM_INTERNAL_SECRET;

    await fetch(`${studioUrl}/api/telegram`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Authorization": `Bearer ${internalSecret}`,
      },
      body: JSON.stringify(update),
    });
  } catch (err) {
    console.error("[Telegram Router] Failed to forward to Miraz Studio:", err);
  }
  return NextResponse.json({ ok: true });
}

// ... All your existing Personal Portfolio logic remains completely untouched below ...
```

## 5. Supported Telegram Commands & Actions

| Command / Action | Database Mapping | Description |
| :--- | :--- | :--- |
| `/studio` | Queries `contactMessage` & `project` | Displays the Studio Dashboard (New Leads count, Active Projects count, quick buttons). |
| `/studio_leads` | Queries `contactMessage` | Displays paginated recent client inquiries with status (`🟡 New`, `🟢 Read`, `🔴 Archived`, `🔵 Replied`). |
| `/studio_projects` | Queries `project` | Displays paginated list of studio case studies from the database. |
| `[👁 View]` | `studio:lead:view:<id>` | Inspects full client brief (Name, Email, Scope, Budget, Timeline, Message). |
| `[📖 Mark Read]` | `studio:lead:read:<id>` | Updates lead status to `read` in the database (Idempotent). |
| `[📦 Archive]` | `studio:lead:archive:<id>` | Updates lead status to `archived` in the database (Idempotent). |
